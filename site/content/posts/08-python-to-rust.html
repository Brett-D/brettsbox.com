The Jetson was working too hard. On a typical exploration run its load average sat around 20 on six cores: far more work waiting than it had cores to run it on. Most of the heavy lifting was already native code: Nav2 and RTAB-Map are C++, and cuVSLAM and nvblox run on the GPU. The overhead was in the glue I'd written myself in Python. The web dashboard, the Roomba driver, the odometry watchdog and the obstacle detector each used a quarter to a half of a CPU core.

So the rule for this project is now Rust wherever it's practical. Rather than redesign anything, each Python node gets a Rust twin that is a drop-in replacement: same node name, topics, parameters, services and even log lines. One launch argument, rust_nodes, picks which set runs.

The results

CPU use is in percent of one core, measured on the Jetson with both versions running side by side on the same input:

NodePythonRust
Web dashboard server48%10%
Roomba driver31%2.4%
Odometry watchdog26%2.2%
Floor obstacles19%2.5%
Wheel and gyro prep for the EKF8.7%1.2%
Explorer and nav coachRust uses about a sixth

Add up the first five and they went from about 132% of a core to 18%, giving back more than a whole core. Memory dropped too: the dashboard server peaks at 42 MB instead of 165 MB, and the driver and the watchdog at under 30 MB instead of about 75 MB.

The person detector, which finds people in the camera image with a TensorRT network on the GPU and works out how far away they are, is measured per camera frame instead. Its CPU time per frame fell from 45 to 13 ms, the median time from frame to result from 56 to 42 ms, and its memory from 649 to 448 MB. The map gap filler and the keep-out zones node were ported as well, so ten nodes now have Rust versions.

Same output, or it doesn't ship

Faster is easy to claim. The hard rule was that every Rust node has to give exactly the same output as the Python one, and that has to be proven, not eyeballed. Each port came with a test that feeds both versions identical input and compares everything they send out:

  • Odometry watchdog: a 35-minute recorded drive (413,000 IMU samples and 30,700 camera poses) through both. Both forwarded the same 26,084 poses, made the same 87 recoveries and printed the same 577 log lines. The largest difference in any position was about 0.000000000003 m. The same check passed on 17 runs, including injected faults such as tracking loss and a slow reset.
  • Map gap filler: 1,467 recorded and made-up maps, 23.5 million cells, identical.
  • Explorer: the same goals on 572 maps from real drives, including the bump keep-out marks and retries.
  • Person detector: 10,579 recorded frames, identical detections, distances and annotated images, down to the bytes of the JPEG.
  • Roomba driver: a fake Roomba on a virtual serial port, with scripted bumps, cliffs, bad checksums and dropped streams. Both drivers sent the robot exactly the same bytes.

Identical is harder than it sounds

Python, NumPy and OpenCV each have their own quirks, and matching them bit for bit meant copying them on purpose:

  • Rounding: to two decimal places, NumPy rounds 2.675 to 2.68, while Python's own round gives 2.67. The Rust code has to know which one the Python called.
  • Distances: Python's math.hypot is not the C library's hypot; for some inputs they differ in the last bit. That's enough to nudge a decision the other way.
  • Order matters: OpenCV numbers connected blobs in a particular order and NumPy sorts with a particular algorithm. Both had to be reproduced, or ties came out differently.
  • Missing pieces: ROS 2's Rust library has no TF (the transforms between the robot's coordinate frames), so it got a port of ROS's own that gives bit-identical results. NVIDIA ships no Rust bindings for cuVSLAM's messages either, so those are generated from the message definitions.
  • The linker: the standard Linux linker took over ten minutes to link one node on the Jetson. Switching to mold fixed that.

Not on the road yet

Every number here comes from recorded drives and a simulated Roomba. The Rust nodes are now the default, so the next real drive will be the first on Rust. If anything misbehaves, rust_nodes:=false brings back the Python versions.

The code: the Rust nodes are in src/roomba_rs, and the Python-vs-Rust comparison tools in tools/.
